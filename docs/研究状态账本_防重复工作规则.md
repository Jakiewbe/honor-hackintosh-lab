## 二、仍阻塞安装的最小问题

**P0-1：NMXGPU 的真实外部编译输入及对象闭合**：[R1.3-C](R1.3-C_NMXGPU构建来源与对象完整性门禁.md) 核查发现 `srclist.py` 缺失源诊断被调用脚本重定向丢弃，`all-i915.sh` 的编译失败计数不强制令构建失败，且不清理旧 `obj-i915/*.o`；`kext/build.sh` 直接使用对象 glob 链接。所需 drm-kmod、FreeBSD LinuxKPI、Linux 外部 commit/hash、实际 `srcs-i915.txt`、`amd.flags`、无失败对象清单和链接映射仍未闭合。**只证明存在可能的错误路径，不能推断发布二进制真的缺对象。**

**P0-1B：内屏 framebuffer 类别抢占**：[R1.3-D](R1.3-D_发行包证据入口与Intel屏幕抢占风险.md) 确认 NullMoth v1.14.2 `NVRMFBClaim` 以 `IONameMatch=display` 广域匹配且没有 NVIDIA vendor 限定；[Issue #119](https://github.com/nullmoth/nvidia-macos-driver/issues/119) 报告 Intel 内屏无 GUI，[PR #131](https://github.com/nullmoth/nvidia-macos-driver/pull/131) 尚未合并。本机仅有架构相似性，**不等于本机必然黑屏**；后续跟踪该补丁实际合并及版本发布。

**P0-2：Intel eDP/scanout**：`46A6` i915 设备初始化、VBT/EDID、DRM framebuffer backing、XNU CPU 物理映射和实际内屏连续画面尚无完整证据。

**P0-3：生命周期**：`NMXGPUFB` 原生 VBL 注销空实现、timer/terminate、target/worker/object release 的并发安全未证明；此前 `NMIntelFB` 的 R1.2-C 补丁不可直接套用。

**P0-4：RTX 2050**：NVRM/GSP/NVAccel/Metal 无该 PCI ID 可靠 macOS 实机加速证明，且不能替代 Intel 的内屏扫描输出。

**P0-5：用户主力机保护**：硬盘/BitLocker/EFI/BIOS 状态与经实测的完整 Windows 回滚尚无准入验证，因此任何实际安装均禁止。

## 三、每次推进的强制工作方式

1. **先从 GitHub 读取本账本、README、硬件档案、最近一阶段报告和相关脚本/CI 日志**，核对是否已有同等验证；不只凭对话回忆推进。
2. **明确本轮“新增证据是什么”**：固定上游 tag/commit、Git blob、具体调用/编译路径、独立实机报告或能否推翻旧判断；若没有信息增量，报告停滞原因，不制造新任务刷进度。
3. **只解决当前最高优先级未关闭的 P0**。不为尚未验证的底层图形链路优化 VBL、Metal、UI、普通安装脚本或自动化。
4. 测试分级：**静态代码存在 ≠ 对象编译成功 ≠ 链接成功 ≠ kext 加载成功 ≠ 点亮显示器 ≠ 真实 Metal 渲染 ≠ 主力机安全可用**。每一等级需独立证据；没有真实证据就保持 NO-GO。
5. 更新优先级时同步修改**本账本 + 对应阶段报告 + README 索引**。用户已确认内屏输出 Intel，不能反复要求同一测试。新的 CI 仅在验证独立、可复验的真问题时拟定，**只能由用户手动触发**。
6. 未完成全量备份和回滚验证前，禁止触碰用户主力 Windows、BIOS、EFI、分区和安全设置；不签名、安装、加载内核扩展，不执行上游一键安装器。
