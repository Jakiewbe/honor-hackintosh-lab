# R1.2-H｜技术路线重新聚焦与暂停条件（HONOR GLO-FX6P）

**研究日期：2026-10-12（UTC+08）｜判定：REFOCUS / VBL-PATCH-FROZEN / RUNTIME-NO-GO。**

**不是否定 R1.2-C～G 的成果，而是结束低价值的局部优化，重新按最终目标决定研究资源。** 本项目要判定：荣耀 GLO-FX6P（i5-12500H / Iris Xe `8086:46A6` / RTX 2050 Laptop `10DE:25A9`）能否安全获得**可用的 macOS 图形环境**，而不是仅产生可以编译的 `NMIntelFB` 对象文件或抽象回调模型。

## 2. NullMoth 的新进展：设备列表与实机证据必须分开

以下以 **2026-10-12 查阅的上游公开仓库为准**；上游更新很快，后续重新核实发行 tag，不能把当前 README 当成永远固定的源码基线。

- [NullMoth Release v1.14.2](https://github.com/nullmoth/nvidia-macos-driver/releases/tag/v1.14.2) 已发布预构建包及 Mac 配套 App。但提供二进制**不意味着我们可以从公开来源完全复现所有 Darwin RM 构建参数，也不意味着 RTX 2050 运行可靠**。既有 R0.7 对固定 r610.57.04 源码缺少 Darwin `compile_cmds.sh` 的结论仍应保留，并需判断更新的打包方式有没有消除可复现性缺口。
- [CARD-SUPPORT.md](https://github.com/nullmoth/nvidia-macos-driver/blob/main/docs/CARD-SUPPORT.md) 明示 Ampere 包括 RTX 30 等设备列表覆盖，但物理验证 **Pending**；已验证的主要对象是 RTX 5060，另有 RTX 5070/5080 报告。设备 ID 列表包含 `25A9` 对应 **RTX 2050**（[nvidia_gsp_ids.json](https://github.com/nullmoth/nvidia-macos-driver/blob/main/app/Resources/nvidia_gsp_ids.json)），**仅此不能视为可用**。
- [RELEASE-1.14.0.md](https://github.com/nullmoth/nvidia-macos-driver/blob/main/docs/RELEASE-1.14.0.md) 新增实验性 **NMXGPU**，目标包括 Intel Iris Xe、Arc 与部分 AMD GPU；但上游发布说明明确指出：**它尚未在真实 Intel/AMD GPU 上运行得到成功验证**。1.14.2 发布说明仍保留该缺口。
- [Issue #135](https://github.com/nullmoth/nvidia-macos-driver/issues/135)：第三方报告 MSI GF63 / i5-11400H / GTX 1650 Max-Q / Intel UHD `8086:9A68` / 无 MUX：系统可报告 NVIDIA `Metal 3`，但**内屏停留启动进度条**，报告称唯一的 framebuffer 来自 NVIDIA。它不是 RTX 2050 成功/失败证据，且信息是贡献者自报；但具体说明了**GPU 识别、Metal 字样、内屏点亮**并不等价。
- [Dortania OpenCore Hardware Limitations](https://dortania.github.io/OpenCore-Install-Guide/macos-limits)：传统 OpenCore 指南的 Intel 笔记本 CPU/iGPU 支持停留在较早代际，并没有为 Alder Lake Iris Xe 提供官方原生加速方案。实验性第三方驱动与传统 macOS 原生兼容性须分开讨论。

### 重要修正

原研究一度将 `NMIntelFB` 作为事实上必须攻克的主干，并围绕 VBL 投入了 R1.2-A～G 多轮。这对发现具体代码隐患有价值，但**没有先证明我们的荣耀内屏恰好需要、也可以使用该模块**。因此不应以 R1.2-C/G 的绿色 CI 作为推进安装的信号。

同样，当前最新发布的 NullMoth 预编译包是一个值得**审计**的证据线索，而不是可信任的安装步骤。不得直接运行 `1401`、`install.sh`、第三方 EFI、驱动 package 或绕过 macOS 安全策略来消除研究阻塞。

## 3. HONOR 专项关键路径和门禁

| 优先级 | 先决问题 | 合格证据 | 当前判定 |
|---|---|---|---|
| **P0-A** | **内屏 eDP / HDMI / USB-C 实际挂在哪块 GPU？是否有物理 MUX/Advanced Optimus？** | 该型号官方技术说明/拆机电路证据，配合 Windows“高级显示 → 连接到”的逐显示器输出及 NVIDIA 控制面板 PhysX 连接图；最好双来源相互印证 | **UNKNOWN** |
| **P0-B** | **RTX 2050 的完整原生驱动是否真的有实机成功？** | 与 `10DE:25A9` 或可信等同设备明确对应的日志：NVRM attach → GSP firmware → NVAccel → Metal app 真实渲染 → 输出画面，记录 macOS/driver 版本 | **NO PHYSICAL PROOF** |
| **P0-C** | **Intel Iris Xe `8086:46A6` 内屏路线是否成立？** | NMXGPU 或其他可信项目在同代同 PCI 设备上的 firmware、显示扫描输出和图形应用真实验证；不能只看设备表或 VBL timer 构建 | **EXPERIMENTAL / NO PHYSICAL PROOF** |
| **P0-D** | **Intel 12500H 异构 CPU 的 macOS 15 启动前提是什么？** | 同代硬件明确包含 P/E 核、电源管理、ACPI、SMBIOS/UEFI 所需配置的完整可复现报告 | **UNVERIFIED** |
| **P1-A** | NVAccel 公开源头是否足以完全复现 macOS 构建？ | 在固定 NVIDIA 610.57.04 Commit、NullMoth release tag、macOS SDK 环境下有精确编译命令/生成步骤，来源可审计且完整链接 | **BLOCKED FOR PINNED SOURCE** |
| **P1-B** | 非主力机器/隔离测试及完整 Windows 回滚是否可行？ | BitLocker/Recovery/EFI 独立备份和完整恢复演练，不能以供应商撤销入口替代主机恢复保证 | **NOT VERIFIED** |

**判定规则**：若确认该荣耀属于 muxless，内屏只挂 Intel Xe 且 Intel 显示驱动仍未证实，那么即使 NVIDIA headless Metal 工作也不足以实现目标中的**内屏可用 macOS**；除非存在被独立验证的安全复制/扫描输出链，否则该路线应停止。相反，若有物理 MUX 或 NVIDIA 直连的外屏，才值得重新评估独显优先路线，但 **不允许据此直接在主力机改 BIOS/EFI 或启动 macOS**。

## 4. 可立即执行的只读调查

已创建 [`scripts/r12h_windows_readonly_display_probe.ps1`](../scripts/r12h_windows_readonly_display_probe.ps1)：

- 运行于 Windows PowerShell 5.1+；只显示 GPU 名称与 PCI ID、驱动版本、PCI 位置、活动显示器连接技术代码。
- **不需要管理员权限、不执行下载、不写盘、不读磁盘分区、不修改驱动、注册表、BIOS、EFI 或显示设置**；不输出设备序列号。
- 脚本对 eDP/HDMI/USB-C 的 GPU 走线只提供**线索**，绝不将 WMI `VideoOutputTechnology` 冒充显卡所有权映射。

**下一项最有价值的用户侧证据**：在 Windows 正常状态下，打开“设置 → 系统 → 显示 → 高级显示”，查看内屏的“连接到：Intel/NVIDIA”字段，并在 NVIDIA 控制面板“配置 Surround、PhysX”中查看显示器与 GPU 的连线图；如果已经接有 HDMI/USB-C 外屏，分别观察各自的“连接到”。**仅观察，不点任何切换/应用按钮**。分享时遮盖个人信息。

## 5. 当前路线与停止条件

**立即执行（研究）**
1. 冻结 R1.2-C 的部署候选；R1.2-D～G 停留在静态证据与参考模型。**不开新 VBL 补丁，不重复跑 CI 刷绿。**
2. 只读取得 HONOR GPU/内屏拓扑，确定是否存在物理可行的 macOS 输出路径。
3. 跟进上游可核对的 **RTX 2050 / Ampere 笔记本物理验证**与 **NMXGPU 对 Iris Xe 的真实运行**；把设备表、第三方报告、开发者声称、独立重复验证分等级。
4. 单独审查 v1.14.2 预编译包、公开源码对应 commit 与 NVIDIA Darwin 编译参数来源之间的可复现性；不能因为存在打包成品就判定可重建或可信安装。

**触发继续的条件**：只有当 P0-A 明确，加上 P0-B 或 P0-C 至少一条真实图形/扫描输出链路得到充分证据时，才考虑重新打开显示驱动问题；之后还需满足 P0-D 和安全回滚。若长期拿不到上述证据，明确终止主力机 Hackintosh 安装尝试，比持续修改不可验证的驱动代码更符合项目目标。

**本轮输出性质**：技术路线与安全门禁审计，不是对硬件的最终否决，也不是 macOS 安装指南。**不得签名/加载 kext，不运行一键安装器或第三方脚本，不修改主力荣耀 Windows、BIOS、EFI、磁盘与安全设置。**
