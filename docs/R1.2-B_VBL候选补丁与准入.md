### 编译成功后的安全复查：仍为 NO-GO

审查 `patches/r12b_vbl_workloop_gate.patch` 发现下列**条件性风险**（未观察到实机崩溃）：

1. **P0：外部 VBL 回调同步停止服务的对象寿命。** `vblFire` 中调用 `snapshot.proc(snapshot.target, snapshot.ref)` 后，仍依次执行 `snapshot.target->release()`、`me->fVblCalls++` 并读取 `me->fVblPhase/fVblTimer`。如果外部回调经同步再入导致当前 framebuffer 对象销毁或事件源解绑，需要证明 `me` 在这些访问结束前仍有独立所有权。当前补丁与离线模型**没有建立这个证明**。
2. **P0：回调中重入 `disarmVbl` 的资源释放次序。** `IOWorkLoop::runAction` 门锁可递归进入；`disarmVbl` 会取消、移除并释放当前计时器。必须证明从当前计时器 action 内进行此流程不会出现不合规范的源释放、等待死锁或未完成的事件回调。之前通过的模型显式**排除此情况**。
3. **P1：已发布设备的计时器运行期故障。** `vblFire` 在 `setTimeoutUS` 失败后仅切换 `kVblStopping` 并打日志，尚未定义对已发布 IOFramebuffer 会话的完整失败回退；不能把“后续不排队”视为仍可正常显示。
4. **P1：虚拟模式未包含在本次编译目标。** 本次 workflow 未定义 `NMINTELFB_VIRTUAL`；其中独立采样定时源的完整构建/释放路径仍未经目标编译验证。

**准入决定：** 候选补丁标记为 **BUILD-PASS / RUNTIME-BLOCKED**，维持禁止加载和安装。下一阶段 R1.2-C 应优先建立 *callback-invoked unregister/stop* 的故障注入与 stop/drain/owner 引用顺序，并对重入场景做显式可证明的处理；任何未完成的工作不得被重复绿色 CI 替代。

## 候选改动

1. **VBL 调度**：使用 `IOTimerEventSource` 替代裸 `thread_call_t`；事件源挂载到 `getWorkLoop()`，在定时回调末尾仅当状态保持 `ARMED` 时重新设置下一次超时。
2. **事件回调表**：通过公开的 `IOWorkLoop::runAction` 串行化 `registerForInterruptType`、`unregisterInterrupt` 和 `setInterruptState`；不调用受保护的 `closeGate/openGate`。
3. **回调快照与所有权**：注册回调时 retain `OSObject *target`，注销时 release；调用前再 retain 一份快照，避免回调内的同步注销直接释放当前回调目标。
4. **停止状态机**：`NEW → ARMED → STOPPING → DRAINED`；停止时取消超时、清除回调表、移除事件源并 release；阻止 `STOPPING` 阶段正常重排队。
5. **部分初始化失败回退**：真实和虚拟两条 `start()` 路径在 `armVbl()` 失败时拒绝发布已就绪的设备，尽力移除事件源并调用 `IOFramebuffer::stop(provider)` 回退。
6. **虚拟模式中的第二定时器**：清理原本独立的 `fTimer` 采样事件源；目前仍需要额外的编译模式覆盖以及外部回调再入测试。

## 证据与尚未满足的安全条件

静态逐行对照已经确认：
- R1.1 的两个修改文件仍与固定 commit 对应；
- R1.2-B 的四个 unified diff 区块均准确匹配 **已应用 R1.1 的 intelfb.cpp**；
- 补丁后预计保留 R1.1 的 `actualSize` 和 NVAccel 目标容量校验；
- 旧 `thread_call_allocate(vblFire, this)` 调度路径在新代码中已移除；
- 回调注册、注销和状态更新的入口均改为 workloop 同步动作。

但以上**只是静态上下文与源码约束检查**，尚未在 macOS SDK 中编译这份 R1.2-B；也没有在内核执行并发测试。

仍有下列 **BLOCKER**，即使云端编译成功也不能进入实机安装阶段：

- **同步重入 stop**：当 VBL 回调（或其目标）在事件源 action 调用栈中重新进入 `IOFramebuffer::stop` 时，`removeEventSource`、`release` 与 owner 的引用寿命需要独立证明。
- **注销返回语义**：外部线程的 workloop gate 进入可以等待当前 action 结束，但回调中的递归注册/注销与目标对象析构回调仍需测试。
- **定时器运行期调度失败**：候选在重排队失败时停止后续调度，但目前**没有完成自动摘除/撤销已发布 framebuffer**的安全状态恢复，可能导致无 VBL 的显示会话。
- **其他启动失败路径**：PCI memory enable 状态、IOFramebuffer 超类的半初始化路径、虚拟采样源 `addEventSource` 失败清理仍需审计。
- **设备和内核兼容性**：HONOR `8086:46A6` 真实 scanout、NVIDIA `10DE:25A9` Metal、macOS KernelCollection 导出和签名/加载均无证据。
