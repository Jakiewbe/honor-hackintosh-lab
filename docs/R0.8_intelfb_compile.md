# R0.8 Intel framebuffer native compilation

The upstream NVAccel build needs NVIDIA-generated `src/nvidia/_out/Darwin_x86_64/compile_cmds.sh`, which is **absent** from public NVIDIA r610.57.04 sources. R0.8 runs an independent native compile of the original `NMIntelFB/intelfb.cpp` source, without synthesizing missing NVIDIA compiler flags.

## Manual run

Open [HONOR R0.8 NMIntelFB native compile](https://github.com/Jakiewbe/honor-hackintosh-lab/actions/workflows/intelfb-native-compile.yml). Choose **Run workflow → main → mode: compile**. Only choose `link` if compilation has already succeeded, and you want to test the unsigned kext link. Check Actions billing/usage before running.

The job pins upstream NullMoth commit `0960b2ef5dbc4a573056d4c8e042a5bd2e15d651` and checks seven existing known blob SHA values. It then parses the original NMIntelFB Info.plist and compiles `intelfb.cpp` with Xcode 16 kernel SDK for x86_64 using `-fapple-kext -mkernel`. The original source itself is never modified.

A failed compile is meaningful: look for `R08_INTELFB_OBJECT_COMPILE_FAILED` and examine the first compiler error; this is not yet evidence of a GPU limitation. A pass is `R08_INTELFB_OBJECT_COMPILE_PASS`, proving **translation-unit compilation only**. Even a successful `link` does not prove that the binary can load on macOS or drive Intel `8086:46A6`.

Diagnostics are retained as text files for 7 days; neither the object nor executable is uploaded. No software is installed, loaded, or code signed. The user's primary Windows system, EFI and BIOS remain untouched.
