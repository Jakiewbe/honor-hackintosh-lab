## 2. 本轮新增 P0：发布版 NVRMFBClaim 仍可夺取 Intel framebuffer 匹配位置

[上游 Issue #119](https://github.com/nullmoth/nvidia-macos-driver/issues/119) 的 muxless Dell 7610 使用 Tiger Lake-H Intel `8086:9A60` + RTX 3050 Laptop `10DE:25A2`（**并非本机 RTX2050/46A6**）。其日志显示：
- NVRMFBClaim 对 IGPU 占用 `IOFramebuffer` 匹配类别；
- dGPU 本身报告 `heads 0 / connectors 0`，不能提供本机内屏的显示端点；
- WindowServer 使用虚拟显示，用户报告内屏没有正常图形桌面。

这是一份**第三方设备日志及对照实验**，不是我们的 HONOR 实机验证。其上游 [PR #131](https://github.com/nullmoth/nvidia-macos-driver/pull/131) 提出在 NVRMFBClaim 的 `Info.plist` 中限定 NVIDIA vendor/class。**截至本轮审查 PR 仍为 OPEN，未合并。**

更重要的是，本轮直接审查了 **v1.14.2 固定版本** [`kexts/NVRMFB/fb/Info.plist`](https://github.com/nullmoth/nvidia-macos-driver/blob/1083a98db33a0bb824290556de255f9a95ca5403/kexts/NVRMFB/fb/Info.plist)，Git blob **`1bd2586d1710e9505c97dbac6ee4a2f2932e34f6`**：`NVRMFBClaim` 的 Personaliy 仍然是：
```xml
<key>IOClass</key><string>NVRMFBClaim</string>
<key>IOProviderClass</key><string>IOPCIDevice</string>
<key>IONameMatch</key><string>display</string>
<key>IOMatchCategory</key><string>IOFramebuffer</string>
<key>IOProbeScore</key><integer>30000</integer>
```
此 personality **没有限制 NVIDIA `10DE` 的 PCI vendor 或 class**。对内屏经 Intel 输出的 HONOR，这属于一项**无需等待 i915 完整驱动构建就已经存在的先决集成风险**。PR #131 的设计与 #119 的第三方结果说明问题有可审计的修复方向，**但目前不能宣称修复已合并、发布、对 HONOR 安全，或者已经实测**。

**注意：** 这不意味着 `NVRMFBClaim` 本身在本机必然造成黑屏；需要结合真实匹配优先级、系统组件、当前配置和回调生命周期。这里的判断是发布版存在广域匹配结构、相似硬件有实机负面报告，所以内屏链路准入不得忽略。

## 3. 这次新增一项真正会产生不同证据的手动 CI（不是编译）

[GitHub Actions：R1.3-D Release Provenance Index](../.github/workflows/r13d-release-provenance-index.yml)。

- **手动 `workflow_dispatch`；Linux 临时 GitHub runner；无需主力电脑，不安装 macOS 或 kext。**
- 下载**固定 v1.14.2** 公开发布的 `SHA256SUMS.txt` 及 `nullmoth-nvidia-1.14.2.tar.gz` 到 runner 的临时目录；核对 **完整 SHA-256**，校验失败即停止。
- 使用 **`tar -tzf` 只列文件名，不解包、不加载、不执行归档脚本/二进制**。从清单分类检索 NMXGPU、`srcs-i915.txt`、`amd.flags`、`obj-i915`、外部 `drm-kmod/freebsd-src`、Linux 源树、编译依赖及链接日志等路径。
- 只上传 **SHA 证明、路径总表、分类 JSON 与局限说明文本**；归档文件及里面的 `.kext`、二进制、固件不会上传。
- 该流程已由用户手动运行并成功：**[Actions #38217837373](https://github.com/Jakiewbe/honor-hackintosh-lab/actions/runs/38217837373)**；SHA 校验及路径分类均 PASS；仅上传 5 份文本证据，未执行程序、未解包安装、未上传任何二进制。
- 如果清单中**有**对应源码/对象/manifest，就进一步只读核对是否与发布版精确对应；如果**没有**，只能说明**这个具体发行归档未提供相应路径**，还需要上游发布者的实际编译输入，不可推断其私有机器没有相应源文件。

与此前 R1.3-C 不新建“重复编译 CI”的约束**不冲突**：这项工作只获取尚未检查的发行资产清单，是来源证据调查，不会重复编译。
