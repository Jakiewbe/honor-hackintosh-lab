# 00｜项目目标、愿景与成功定义

## 背景和愿景

本项目起于对 **Intel + NVIDIA 笔记本在 macOS 下是否有新的可行适配技术** 的调查。目标设备是用户**主力 Windows 笔记本**荣耀 GLO-FX6P。项目不以快速得到一个能进入安装器的 EFI 为成功，而是验证工程可行性并有根据地决定是否值得尝试 macOS。

**愿景：建立一个公开可审查、源码有据、实验可复现、失败可回退的 Intel Alder Lake-P + NVIDIA Ampere macOS 图形适配研究工作台。** 所有适配主张必须对应具体设备、系统版本、源代码和完整证据链；研发成果即使最终不能装机，也应能解释为什么不能。

用户后来明确转向**由本仓库自主研发适配代码**，不等待 NullMoth 私有构建记录。因此本仓库的定位从“验证第三方 N 卡传闻”升级为“Intel 内屏自主显示驱动工程研究”，但不隐瞒技术与测试资源的限制。

## 三层目标与严格顺序

| 级别 | 研发目标 | 真正验收 | 当前情况 |
|---|---|---|---|
| **L1（当前）** | 让 `8086:46A6` 的 Intel eDP 内屏持续显示 macOS 基本桌面，允许纯软件渲染 | 具有已知硬件 PCI ID 的**隔离非主力机器**真实完成启动、有效 IOFramebuffer、画面持续更新、输入正常、干净停止和恢复 | **未证明** |
| **L2（后续）** | Intel Xe GPU 命令提交、用户态图形驱动及加速（包括 Metal 可行性） | 实物 GPU 的显存/队列/同步与真实渲染测试，不能只显示 “Metal 3” 字样 | **未证明** |
| **L3（远期）** | RTX 2050 `10DE:25A9` 完整加速与 NVIDIA→Intel 混合显示 | 实物 NVRM/GSP/NVAccel 渲染、跨 GPU 复制/同步、Intel 内屏输出和长期稳定性 | **未证明** |

**软件静态链接并非可加载性；可加载性并非画面刷新；画面刷新并非 Metal；Metal 识别并非用户可用。** macOS 15 WindowServer 对第三方无加速 IOFramebuffer 是否完整接受，目前需要实物证据，不能当作已解决的系统性质。

## 工程价值原则

1. **第一性原理、以源码和硬件行为为准。** 不附和不可靠的“已攻克 NVIDIA”宣传，不盲信单次截图、预编译 EFI 或自动化 SUCCESS。
2. **最短可证伪路径**：当前先解决 Intel 内屏 L1 的依赖/硬件显示路径；否则不投入 RTX Metal、VBL 微调和 UI 美化。
3. **有界研发与明确停止**：构建缺少依赖、内存语义不明、并发安全不能证明时明确 BLOCKED，严禁凭 Stub/猜地址前进。
4. **主力 Windows 零侵入**：项目早期仅公开资料、离线源码/模型和手动托管 CI；硬件隔离验证及恢复方案另设授权。
5. **可交接**：每阶段固定输入 commit、证据链接、决策、未证明项、复现实验入口、下一个最小任务。

## 阶段性非目标

- 不是生成可直接下载的“荣耀黑苹果 EFI”，不承诺兼容某个 macOS 安装盘。
- 当前不研究一键替换 OpenCore、关闭 SIP/安全启动、注入未知 kext 的快速装机捷径。
- 不强行将 Nvidia 设备表中 `25A9` 的出现当成支持 RTX 2050。
- 不为获得 CI 绿灯伪造驱动成功，或将旧参考模型堆叠成无穷补丁。
