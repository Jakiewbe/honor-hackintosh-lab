
# R38 前置：free 顺序的实测（2026-10-19）

独立审计指出"callback quiescence 必须早于破坏性 NISO 清理"。本轮把它变成**可测的数字**。

## 方法与可复现性

把 ogkm-r3 补丁与 ogkm-r36-try-free-result 依次应用到固定 OGKM 树（core.autocrlf=false、
补丁先归一化为 LF），得到候选文件：

`
sha256 = 895de47ae03abc08d9a032f8f083db0be76aa5aa45317ebe37d7720a54c657cb
`

与 R36 文档登记的"最终 OGKM KAPI"哈希**逐字节一致**，说明这份候选就是被审计的那份。

## 工具与结果

	ools/check-kapi-free-order.py 读取该候选，定位 KmsFreeDevice 体内各步骤偏移：

| 步骤 | 偏移 |
|---|---|
| 
vKmsKapiFreeNisoSurface(semaphore) | 112 |
| 
vKmsKapiFreeNisoSurface(notifier) | 170 |
| NVKMS_IOCTL_FREE_DEVICE | 497 |
| callback quiescence（
vkms_xnu_try_close_kapi） | 811 |

**RESULT: FAIL**，四项：

1. callbacks 在 semaphore 释放**之后**才 quiesce
2. callbacks 在 
otifier 释放**之后**才 quiesce
3. callbacks 在 FREE_DEVICE **之后**才 quiesce
4. NISO 表面在 FREE_DEVICE **确认成功之前**就被释放

第 4 项比审计描述更严重：若 FREE_DEVICE 返回失败（R36 的保留路径），
**NVKMS 仍持有这些句柄，而对应表面已被解映射**。

## 这不是把 FAIL 当结论

工具把顺序变成可核对的整数，任何人可用同一条命令复现。修复方向（R38 草案，未实施）：

1. 把 
vkms_xnu_try_close_kapi 拆成 	ry_quiesce（只做 callback 停止与拒绝）与 	ry_close（释放 wrapper）；
2. KmsFreeDevice 顺序改为：**quiesce → FREE_DEVICE（失败即保留，不动 NISO）→ NISO 释放 → close**；
3. 顺序检查在修复后应转 PASS；工具本身**尚未接入门禁**，因此不会把构建变红。

## 边界

这只是源码顺序证据，不是运行证据：没有实机 callback 并发、没有真实 NISO 解映射、没有内核调度证明。
"顺序正确"是必要条件，不是"关闭安全"的充分条件。

## R38 草案：把 quiesce 挪到破坏性清理之前（已用检查验证转 PASS）

### 两份草案（均 git apply --check 通过）

| 补丁 | 目标 | 规模 |
|---|---|---|
| draft-r38-os-quiesce-split.patch | kexts/NVRM/os-nvkms-xnu.cpp | 39 行 |
| draft-r38-ogkm-quiesce-order.patch | 
vkms-kapi.c（叠在 R36 之上） | 37 行 |

### OS 侧

把 
vkms_xnu_try_close_kapi 拆成两个：

- 
vkms_xnu_try_quiesce_kapi(popen)：只做"拒绝新事件 + 取消/释放 event call"，
  **不设 closing**（否则后续 FREE_DEVICE 会被 
vkms_ioctl_from_kapi 拒绝）、不关 NVKMS、不释放 wrapper；
- 
vkms_xnu_try_close_kapi(popen)：先调 quiesce，再关 NVKMS 与释放 wrapper（幂等：closing 已置则拒绝）。

### OGKM 侧

KmsFreeDevice 顺序改为：

`
quiesce（失败即返回 NV_FALSE，什么都不动）
  → NVKMS_IOCTL_FREE_DEVICE（失败即返回 NV_FALSE，NISO 仍未动）
    → nvKmsKapiFreeNisoSurface(semaphore / notifier)
      → nvKmsKapiTryClose 的 close 部分（关 NVKMS、释放 wrapper）
`

### 验证

在 R36 候选树（sha 895de47a…）上应用 OGKM 草案后，重跑 	ools/check-kapi-free-order.py：

| 步骤 | R36 | R36 + R38 草案 |
|---|---|---|
| quiesce | 811 | **255** |
| FREE_DEVICE | 497 | **655** |
| NISO semaphore | 112 | **990** |
| NISO notifier | 170 | **1048** |
| 结果 | **FAIL（4 项）** | **PASS** |

以及 	hread_call_free 拒绝后的重试策略。
