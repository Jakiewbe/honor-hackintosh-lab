# NVIDIA 离屏闭环：缺口清单（2026-10-18，R34）

唯一优先级依据。三桶分类，**只有第一桶可在本仓库推进**。

## 一、我们能编译/可推进的部分

| 事实 | 数值（最近门禁 39084082896） |
|---|---|
| 编译单元 | 16/16 exit 0，告警零增量 |
| 链接目标 | NVAccel 248,768 B、生产 NVRMFB 315,928 B、NMIntelFB 44,824 B、虚拟 58,752 B |
| 补丁序列 | 27 个，正反向树哈希复原（`ea9467f4…` → `b700fe13…` → `ea9467f4…`） |
| NVRM 单对象 | 定义符号 **138**，未定义 **473** |

**结论**：这 16 个单元构成的是"NVRM 的一个子集 + 两个 framebuffer + accel + 两个 Intel kext"，
可以编译、可以链接，但**不构成可加载的完整 NVRM**（未定义符号 473 个，主要是内核 KPI 与 OGKM 内部符号）。

可继续做的（无需实机）：
1. 逐个归类那 473 个未定义符号：属于内核 KPI（`_IOLock*`、`_OSAddAtomic*` 等，链接时由 kernel 提供）还是属于 OGKM（`nvKms*`、`Rm*`）。
2. 对属于 OGKM 的部分，核对固定版本 `e4a5faa2…` 里是否确有对应源码；有则纳入门禁编译，无则记为结构性缺口。
3. 只做这些，不改变任何已闭合的生命周期/并发合同。

## 二、需要实机才能推进的部分

- `KEXT-LOAD`：加载后是否出现 NVRM 的 RM/GSP 初始化日志。
- `GPU-RUNTIME`：GSP 引导、channel 建立、DMA/GPUVA 映射。
- `METAL` / 像素读回：离屏渲染与回读。
- 任何"加速是否真的发生"的判断。

以上全部 **NO-GO**，且按项目规则需要用户逐次授权设备操作。

## 三、结构上做不到的部分（已用证据确认）

| 事项 | 证据 |
|---|---|
| 发行版 NVRM 含约 **7.93 MB 均匀高熵、无容器头、无字符串**的不透明载荷，无法从源码生成 | `REA-NVRM-BINARY-20261018.md` |
| `nvKmsClose` / `FreeDevice` 为 `void`，关闭失败**无法向上传播**；只能在调用侧观测（R21 的计数） | `R23/R24` 文档 + XNU 无关，属 OGKM 接口 |
| 驱动**无法拒绝系统睡眠**：XNU `IOServicePM.cpp:4525` 把负返回值等同 ack implied | `R24-SUSPEND-CONTRACT-20261018.md` |
| 内屏（Intel 46A6）现有显示所有权归 macOS 自带驱动；发行包**不含** Intel kext | `INTEL-TRACK-20261018.md` |

## 四、因此"离屏闭环"的当前位置

```
源码/构建   ✅ 可复现（27 补丁、16/16、4 个链接目标）
初始化      ⛔ 未验证（需加载）
离屏渲染    ⛔ 未开始
像素读回    ⛔ 未开始
错误传播    ⚠️ 部分（拒绝关闭已可计数，但不可传播）
安全结束    ⚠️ 部分（R24/R27 消除了争用与劈裂窗口，P0-1 仍 BLOCKED）
```

距离目标还差**整整三个验收层级**（KEXT-LOAD → GPU-RUNTIME → 像素读回），全部需要实机。
