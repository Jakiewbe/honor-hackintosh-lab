## 2. 这次交付的脚本为什么不会再"第一次在你机器上跑"

- **不再装任何 LaunchDaemon**。写 `/Library/LaunchDaemons` 是整条链上最脆的一步，而它只为一件事存在：
  开机时把日志抓下来。但 macOS 统一日志本身**落盘**，重启后照样能按时间查。
  于是 `go` 只写两个 NVRAM 变量，重启，`report` 直接查日志。**少一个会失败的东西，就少一种半成品。**
- **命令只有一个，动作只有一个**：`go` → 重启 → `report`。不装、不卸载、不重建 KC、不改 boot-args、
  不调用 `shutdown`（自查断言盯着）。
- **自锁保护**：`go` 把 `nullmoth-nv-starts` 预置为 1，驱动这次开机启动一次后计数变 2 永久自锁。
  即使 panic 也不会反复重启（这正是 v2 的坑，现在反过来用）。
- **每一条输出来源都有断言**：43 条断言覆盖 go 成功/守卫写失败/remove 删不掉/没跑过 go/
  已重启/未重启/有 panic/固件没读到/驱动没启动/status/cancel/未知子命令/报告落盘/系统路径缺失/报告非空。

自测命令（本机就能跑，不需要 Mac）：

```bash
bash tests/command_scripts/test_trial.sh     # → 合计: PASS=43 FAIL=0
```

测试怎么模拟真机：`tests/command_scripts/stubs/` 下的 `nvram`（有状态，键值存文件，支持
`G1_STUB_FAIL_SET/DEL` 注入故障）、`sysctl`（给开机时间）、`log`（喂日志固件）、`kextstat`、`ioreg`。

## 4. 现在请你只做一件事

把 U 盘里最新的 `G1-试跑一次.command` 拖进终端（或者在它所在目录）：

```bash
bash ./G1-试跑一次.command
```

它会：写守卫=1、删掉 `nullmoth-remove`、告诉你重启。**然后重启。**
重启后等 90 秒，同一个目录：

```bash
bash ./G1-试跑一次.command report
```

`report` 会打印 A–G 七段：本次开机日志、最近 2h 全量日志（另存一份到 U 盘 `results/`）、
关键标记计数、panic 检查、驱动现状、**结论**、**下一步该做什么**。

发回来只要两样：终端最后几十行 + `results/report-*.txt`。

### 结果怎么看（脚本里也写了）

| 结论 | 含义 | 下一步 |
|---|---|---|
| `固件被读到了` | **新边界**：84 MB GSP 固件第一次被真正读进驱动 | 再重复跑一轮确认可重复；稳定后才谈装 NVRMFB/NVAccel |
| `固件仍然没读到（vnode_open failed）` | 文件路径/权限/校验问题 | 脚本直接给 `ls -l` 和 `shasum -a 1` 命令与正确值 `f1197102…565ce` |
| `驱动这次没启动` | 守卫锁着，或没重启成功 | 再跑一次 `go`（每轮实验都要先 go，一次机会用完即自锁） |
| 有 probe 但没有固件相关行 | 停在中间某步 | 看 B 段原文最后几行 |

反悔随时：`bash ./G1-试跑一次.command cancel`（驱动关回去，下次开机不启动）。

## 5. 我这边的规矩（写下来，免得再犯）

1. 交付前**必须在本机用假 nvram/sysctl/log 跑过**，跑不过不交。
2. 报告类脚本**先写一行头**，任何早退都不允许留下 0 字节文件。
3. 不许有"安装→重启"这种跨开机的自主动作（v2 的教训），跨开机的部分一律交给人按一次回车。
4. 说"改好了"必须同时给出：改了什么、哪条断言证明、失败会长什么样。
